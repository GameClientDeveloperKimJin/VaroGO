# Stage 02 Z2 — 교대 발판

대상 씬: `Assets/01_Scenes/MapDesign/MapDesign_Stage2.unity`

## 적용 규칙

- 처음에는 R1과 B1만 활성 상태다. 자기 역할의 활성 발판에 착지하면 상대 경로의 현재 발판을 즉시 끄고 다음 발판을 켠다.
- 예: R1 → B2 활성화 → B2 착지 → R2 활성화. 반대로 B1부터 시작해도 진행할 수 있다.
- 상대가 서 있어도 충돌이 즉시 사라져 추락한다. 안전한 고정 발판에서 기다리거나 점프 타이밍을 맞춰야 한다.
- 한 발판은 한 라운드에 한 번만 전환을 발생시킨다. 계속 서 있거나 재착지해 여러 단계를 넘길 수 없다. 다른 색 역할과 비활성 발판의 입력은 무시한다.
- 각 경로 6개, 총 12개의 특수발판. 수직 왕복·수평 왕복·생성을 두 차례씩 사용한다. 수직은 4m를 3.2초, 수평은 9m를 4.5초에 이동하고 끝점마다 1.6초 대기하며 활성 상태 동안 반복한다. 생성형은 제자리에 출현한다.
- 비활성화 시 모든 ㄴ자/ㄱ자 구성 충돌체와 시각부가 함께 꺼진다. 마지막 발판에서는 상대를 범위 밖 인덱스로 넘기지 않는다.
- 추락 영역에 들어오면 두 경로의 진행을 처음으로 초기화하고 사망 처리한다. 입구 체크포인트와 기존 개인 부활 시스템을 사용한다.

## 배치와 형태

`Stage02_Rough_20261127/Z2_CooperativeCrossing` 아래 A/B 경로를 편집한다. 이전 정적 경로와 지지 장식은 비활성 보관했다. Z0·Z1 및 Z3~Z8의 구역 오브젝트는 그대로 유지했다.

특수발판은 좌우 위치·간격·방향을 다르게 했고 중간 하강을 포함한 높낮이를 준다. 기본 사각, 넓은 착지형, ㄴ자·ㄱ자 형태를 혼합한다. 고정 대기 발판은 경로 안쪽/바깥쪽으로 크게 엇갈려 배치했다. 모서리 착지도 실제 CharacterController의 발 반경을 포함하여 판정한다. 장식으로만 만든 발판이 아니라 실제 충돌체가 같은 형태로 따라간다.

## 구현

- `Z2Sequence`: 역할별 활성 인덱스, 사용 비트, 활성 시작 시간, 중복 방지와 리셋.
- `Z2Platform`: 기존 `ClockDrivenObstacle`을 사용하여 기존 PlayerController의 이동 발판 탑승 기능과 연동. 이동 위상은 게임 시계와 활성 시각으로 계산한다.
- `Z2NetState`: Fusion 상태 권한과 RPC를 통한 인덱스·활성 시각·사용 상태 동기화. 요청자의 실제 역할·권한·위치를 확인한다. 씬의 NetworkObject에 연결했다.
- `Z2FallReset`: Z2 낙하 영역과 기존 사망·부활 연결.
- 공용 플레이어/기존 기믹 코드를 변경하지 않았다. MapDesign 씬 자체를 빌드 목록에 새로 등록하거나 온라인 로비의 코스로 추가하지 않았다.

## 검증

실제 Play Mode에서 프로젝트의 PlayerController / CharacterController를 수동 틱으로 구동했다. 이동 속도 6m/s, 점프 높이 1.6m, 중력 -25 기준이다.

- 30/60Hz, 두 역할, 왕복의 네 시점, 각 발판 진입·이탈: **192/192 통과**.
- 각 경로를 시작부터 끝까지 순간이동 없이 진행: 두 역할 × 30/60Hz = **4회 통과**. 상대 입력은 안전 발판 도착 시 테스트가 공급한다.
- 8초 연속 탑승: 수직·수평 모두 통과. 테스트상 최대 상대 위치 오차 약 10.5cm.
- 실제 R1 착지 → B2 전환, 서 있기 중복 방지, 다른 역할 거부, 점유 중인 B1 즉시 추락, 양쪽 선행 순서, 추락 초기화 통과.
- 특수발판을 끈 상태에서 인접 고정 발판만 직행하는 10개 경로: 우회 성공 2개(하강 경로 포함). 이동 발판의 운동을 정지시킨 별도 8개 검사는 모두 통과 불가로 확인했다. 모든 가능한 치트/매달리기 우회가 없다는 보증은 아니다.
- Z0·Z1·Z3~Z8의 오브젝트/컴포넌트 직렬화 데이터를 작업 전 백업과 비교하여 변경 0개 확인.

이는 자동화한 오프라인 물리·규칙 검증이다. 실제 두 클라이언트의 네트워크 지연, 재접속, 2인 난이도와 대화 템포는 별도 검증이 필요하다. 동기화 코드는 구현했지만 온라인 실전 통과로 표기하지 않는다.

검증 도구: `Editor/Z2CoopAudit.cs`. Play Mode에서 `Run()`을 호출한다. 결과 및 조정 전후 로그: `Captures/Stage2_Z2/`. 테스트 시 외부 시트 자동 갱신을 일시 중지하고 종료 후 원래 설정을 복구했다. 빌더는 중복 실행을 거부해 수동 편집을 보호한다.

## 다이나믹 지형 개정

- 테라스 최고 높이 11.2m. 4m 승강과 9m 횡단이 필요한 구간을 각각 두 번 배치했다.
- 이동 끝점을 기다리는 탑승/하차 방식으로 192개 검사 및 4회 연속 경로를 검증했다.
- 첫 교환에서 상대 1번이 사라져도 진행할 수 있도록 양쪽에 중립 석조 진입 승강기를 추가했다. 이 승강기는 교대 상태를 바꾸지 않는다. 진입 승강기→첫 테라스→2번 횡단 발판을 양쪽 모두 검사했다.
- 마지막 테라스에서 기존 합류 데크로 내려가는 연결도 양쪽 모두 검사했다.
- 석조 버팀대, 어긋난 돌 단, 승강 가이드, 횡단 레일과 끝점 표식을 추가했다. 장식은 이동 경로를 막는 충돌체로 사용하지 않는다.
- 편집기 도구: Z2DynamicLayout.Apply / AddEntryRecovery. 현재 씬에 적용 완료.


## 점프 간격 보정

특수 발판의 가로·세로 폭을 기존의 85%로, 고정 착지대 폭을 약 88%로 조정하고 착지대를 좌우로 0.3~0.4m 더 벌렸다. 높이·왕복 이동량과 교대 규칙은 유지한다. Z2DynamicLayout.WidenGaps 적용 완료. 조정 후 192개 탑승/하차, 4개 연속 경로, 초입 보조 승강기 및 출구 연결 검사를 통과했다. 이동 정지 시 주요 구간 우회 0/8. 실제 2인 온라인 난이도 검증은 별도 필요하다.
