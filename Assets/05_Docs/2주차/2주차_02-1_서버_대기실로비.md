## 0. 목적

지금은 00_Boot에서 **방 만들기 → 6자리 코드 공유 → 코드 입력 참가 → 게스트 Ready → 호스트 Start** 순서로 진행한다.
코드를 주고받지 않고 **방 목록에서 골라 들어가는** 방식으로 바꾼다.

1. 실행 → **대기실**: 만들어진 방 목록(방 번호·방 이름·인원·버튼)과 [방 만들기]
2. 방에 들어가면 → **로비**(새 씬 `01_Lobby`): Red / Blue를 고르고 준비
3. 두 사람이 모두 준비하면 → **바로** 둘이 함께 코스(`11_SpiralCourse`)로 가서 게임 시작

### 0.1 용어

| 용어 | 뜻 | 씬 |
| --- | --- | --- |
| 대기실 | 방 목록 화면 | `00_Boot` |
| 로비 | 방 안. 역할 선택·준비 | `01_Lobby` (신규) |
| 코스 | 게임 씬 | `11_SpiralCourse` |

> 코드의 `SessionState.Lobby` / `SessionPhase.Lobby`는 "방에 2명이 모여 준비 중"이라는 **단계** 이름이다. 씬 이름 `01_Lobby`와 같은 단어지만 가리키는 대상이 다르다.

### 0.2 결정 사항 (2026-11-03 사용자 확인)

| 항목 | 결정 |
| --- | --- |
| UI | **서버 임시 IMGUI만** (`BootUI`). Shared 계약은 바꾸지 않는다. 정식 uGUI는 나중에 계약을 추가하고 클라가 만든다 |
| 방 번호 | **1000부터 1씩 증가 (임시)**. 방 이름 기본값 = 방 번호 |
| 게임 중인 방 | 목록에 "게임중"으로 표시하고 버튼을 막는다. 단 **파트너가 끊겨 자리가 빈 게임중 방은 [재접속]** 허용 (S2-05 유지) |
| 시작 | 두 사람 모두 준비하면 **즉시** 코스 입장. 카운트다운·방장 시작 버튼 없음 |
| 방장 = Red 규칙 | 없앤다. 역할은 로비에서 직접 고른다 (재접속 때만 빈 역할 자동 배정) |

### 0.3 방 번호 1000+1의 한계 (임시로는 문제 없음)

Photon 클라우드에는 번호를 나눠 주는 서버가 없다. 그래서 **대기실에 보이는 방 번호 중 가장 큰 값 + 1**(방이 없으면 1000)로 정한다.

- 두 사람이 동시에 방을 만들면 같은 번호가 나올 수 있다. 이때 Photon이 `GameIdAlreadyExists`로 거절하면 +1 해서 다시 시도한다(최대 5회, 기존 코드 재시도 로직 재사용).
- 방이 모두 없어지면 다시 1000부터 시작한다.
- 목록 갱신이 몇 초 늦을 수 있다.
- 나중에 방식을 바꿀 때는 번호를 만드는 함수 하나만 고치면 된다.

## 2. 흐름

```
[실행] 00_Boot 대기실 ── 대기실 러너가 Photon 로비에 접속, 방 목록 수신
   │  [방 만들기]  번호 = 최대+1, 이름 = 입력값 또는 번호 → StartGame(IsVisible, 속성 name/ingame=0)
   │  [입장]       해당 번호로 StartGame(참가)
   │  [재접속]     게임중이고 1/2인 방 → 참가 → 코스 씬으로 바로 (S2-05)
   ▼
01_Lobby 로비 ── 마스터가 Runner.LoadScene(01_Lobby), 들어온 사람은 Fusion이 같은 씬을 따라 연다
   │  Red/Blue 선택 → 준비 → (2명, 두 칸 모두 차 있음, 둘 다 준비) → 마스터가 즉시 LoadCourse
   │  [나가기] → Shutdown → 00_Boot 대기실
   ▼
11_SpiralCourse ── 방 속성 ingame=1. 끊김 → PartnerLost(S2-04) → 60초 초과 시 01_Lobby로(ingame=0)
```

### 2.1 목록 버튼 상태

| 게임중 (`ingame`) | 인원 | 버튼 |
| --- | --- | --- |
| 아니오 | 1/2 | **입장** |
| 아니오 | 2/2 | 가득 참 (비활성) |
| 예 | 1/2 | **재접속** |
| 예 | 2/2 | 게임중 (비활성) |

> 재접속 버튼은 처음 보는 사람도 누를 수 있다(빈 역할을 받아 이어서 하게 됨). 테스트 단계에서는 허용한다.

## 6. 클라에 알릴 것 (`전달_서버_to_클라.md`)

- 00_Boot의 `BootMenuUI` 캔버스를 **임시로 비활성화**했다. 서버 IMGUI로 대기실·로비를 테스트하는 동안만이며, 삭제하지 않았다.

- 새 씬 `01_Lobby`(서버 소유)를 만들었고 빌드 세팅 2번에 추가했다.
- 정식 uGUI로 만들려면 방 목록·역할 선택을 위한 Shared 계약이 필요하다(P20, 보류 — P18·P19는 클라가 먼저 씀).
