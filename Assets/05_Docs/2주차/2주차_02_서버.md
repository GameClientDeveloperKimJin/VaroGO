## 2. 계약 추가안 (v0.4 후보 · P11~P15)

정의·오프라인 구현은 **클라(C2-01)** 가 먼저 올린다. 서버는 그걸 받아 Net 구현을 만든다. 이름·시그니처를 바꾸고 싶으면 §8 절차로 클라와 합의.

```cs
// Shared — 정의: 클라 / Net 구현: 서버 / 오프라인 구현: 클라
public enum SessionPhase { Offline, Idle, Connecting, WaitingPartner, Lobby, LoadingCourse, InGame, PartnerLost }

public interface ISessionLobby {            // P11 (C-1028-3 B안)
    SessionPhase Phase { get; }
    bool   IsHost { get; }
    string Code { get; }
    string Status { get; }
    bool   IsFailure { get; }
    bool   PartnerConnected { get; }
    bool   PartnerReady { get; }
    float  PartnerLostSeconds { get; }      // 끊긴 뒤 경과 시간
    event Action Changed;
    void CreateRoom();
    void JoinRoom(string code);
    void Leave();
    void SetReady(bool ready);              // 게스트만
    void StartGame();                       // 호스트만, PartnerReady 일 때만 동작
}

public interface ICheckpointState {         // P12
    int  ActiveOrder { get; }               // 두 역할 모두 도착한 가장 높은 Order (-1 = 시작점)
    bool IsReached(int order, PlayerRole role);
    event Action Changed;
    void ReportReached(int order, PlayerRole role);   // 로컬 플레이어만 (R4)
    bool CanFastTravel(int order);          // (임시) 활성된 지점인지
}

public interface IZoneReset {               // P13
    void RequestReset(int zone, PlayerRole requester);
    event Action<int> ZoneReset;            // 모든 PC에서 1회
}

public interface IPlayerInteraction {       // P14
    void RequestPush(PlayerRole target, Vector3 dir);   // 미는 PC에서 호출
    event Action<PlayerRole, Vector3> Pushed;           // 밀린 PC에서만 (from, dir)
}

// P15: PlayerEvent 끝에 Pushed 추가 (R7)
// GameServices: 기존 Register(...) 유지 + RegisterSystems(session, checkpoints, zoneReset, interaction) 추가
```

## 3. 작업 목록

### 3.1 온라인 세션

| ID | 작업 | 현재 상태 → 바꿀 점 | 완료 기준 |
| --- | --- | --- | --- |
| **S2-01** | Ready 단계 추가 | `OnPlayerJoined` 가 인원 차면 바로 `OnPartnerReady` → 코스 로드. → 자동 시작 제거, `Lobby` 상태로 대기. 게스트 `SetReady` → Networked `GuestReady`. 호스트 `StartGame` 은 `GuestReady` 일 때만 `LoadCourse` | 게스트 Ready 전엔 Start 해도 안 넘어감. Ready 후 Start → 두 PC 동시에 코스 진입 |
| **S2-02** | Ready 동기화·해제 | 게스트가 나가면 `GuestReady=false`, 상태 `Lobby → WaitingPartner` | 게스트 나갔다 재참가 시 Ready 꺼진 상태 |
| **S2-03** | `ISessionLobby` 구현 | `NetBootstrap` 이 구현하고 `GameServices` 에 등록. 기존 public 멤버는 클라 전환 끝날 때까지 유지 | 클라 `BootMenuUI` 가 Net 참조 없이 동작 (C-1028-3 해결) |
| **S2-04** | 파트너 끊김 → 일시정지 | `OnPlayerLeft` 로그만 있음. → `InGame` 중 끊기면 `PartnerLost`, `IGameClock` 정지(장애물 멈춤). 끊긴 역할은 비워두고 대기 | 한쪽 종료 → 남은 PC 장애물 멈춤 + `PartnerLostSeconds` 증가 |
| **S2-05** | 재접속 복원 | 같은 코드로 재참가 → 비어 있던 역할 다시 배정, 코스 씬 로드, 활성 체크포인트에서 스폰, 시계 재개. 제한 시간(예: 60초) 넘으면 로비로 | 재접속 후 스위치·문·체크포인트 상태가 끊기기 전과 같음 |

> ⚠ Shared Mode는 호스트(마스터)가 나가면 게스트가 마스터가 된다. **누가 나가든** 같은 일시정지 흐름을 타야 한다. 씬 NetworkObject(스위치·체크포인트)는 `Is Master Client Object` 로 권한이 넘어가는지 확인 (C-1028-4 확인 항목과 같음).

### 3.2 체크포인트·부활

| ID | 작업 | 내용 | 완료 기준 |
| --- | --- | --- | --- |
| **S2-06** | 공유 체크포인트 상태 | `NetCheckpointState : ICheckpointState`. 코스 씬에 NetworkObject 1개(마스터 소유). 역할별 도착 비트마스크 Networked. `ReportReached` → RPC → 상태 권한에서 기록 → 두 역할 다 도착하면 `ActiveOrder` 갱신 | 한 명만 도착 = 미활성, 둘 다 = 활성. 두 PC 값 일치 |
| **S2-07** | 구역 리셋 요청 처리 | `IZoneReset` Net 구현. `RequestReset` → 상태 권한이 해당 구역 스위치를 `StartOn` 으로 되돌리고 `ZoneReset` 을 모든 PC에 알림. 구역 번호는 클라가 `LocalSwitchState` 에 추가하는 `Zone` 값을 읽는다 (C2-06) | 리셋 요청 → 두 PC 스위치·문 초기화 동시 반영. 죽음만으로는 리셋 안 됨 |
| **S2-08** | (임시 채택) 빠른 이동 검증 | `CanFastTravel(order)` = `order ≤ ActiveOrder`. 순간이동 자체는 클라 | 낮은 우선순위. 시간 남을 때 |

## 6. 2주차 완료 시나리오 (두 PC로 확인)

1. 방 만들기 → 코드 참가 → 게스트 Ready → 호스트 Start → 코스 진입
2. 게스트 창 종료 → 호스트 화면 대기 + 장애물 정지 → 같은 코드로 재참가 → 이어서 진행
3. 체크포인트: 한 명만 도착하면 미활성, 둘 다 도착하면 활성
4. 한 명 낙사 → 그 사람만 활성 체크포인트에서 부활, 퍼즐 그대로 / 리셋 요청 시 두 PC 동시 초기화
5. 밀기 → 상대 넉백 → 떨어지면 "밀려 떨어짐" 메시지
6. 끝나면 `전달_서버_to_클라.md` 에 변경 기록, 계약명세 §9 상태 갱신
