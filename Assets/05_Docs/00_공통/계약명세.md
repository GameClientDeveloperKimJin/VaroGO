# VAROGO 클라이언트 ↔ 서버 계약 명세 v0.3

> 대상: 클라이언트 개발자, 서버 개발자
> 기준 코드: `Assets/03_Scripts/Shared/Contracts.cs`
> 관련 문서: `1주차_00_공통.md` §3–4, `1주차_01_클라이언트.md`, `1주차_02_서버.md`

이 문서는 **"누가 무엇을 만들고, 누가 무엇을 부르며, 무엇을 절대 하지 않는가"**를 정한다.
코드(`Contracts.cs`)는 *모양*만 정하고, 이 문서는 *동작 규칙*을 정한다. 둘이 다르면 **이 문서가 우선**이고, 다른 점을 발견하면 바로 맞춘다.

---

## 0. 한 줄 원칙

1. **클라 코드는 Fusion을 모른다.** `VaroGO.Client`에는 `using Fusion;`이 없다.
2. **서버 코드는 게임플레이를 모른다.** `VaroGO.Net`은 이동·넉백·가시성 계산을 하지 않고, 계약 인터페이스를 *구현하거나 호출*만 한다.
3. **둘이 만나는 곳은 `VaroGO.Shared`뿐이다.** 여기를 바꾸려면 §8 절차를 따른다.
4. **같은 파일을 동시에 고치지 않는다.** 소유자가 없는 파일은 만들지 않는다(§7).

---

## 1. 의존 방향

```
VaroGO.Shared   ← 아무것도 참조하지 않음 (UnityEngine만)
   ↑        ↑
VaroGO.Client   VaroGO.Net
   ↑______________|        (Net → Client 참조는 허용: PlayerController 등)
```

- `Client → Net` 참조는 **금지**. 클라 코드에서 `NetPlayer`, `NetworkRunner` 등을 쓰지 않는다.
- `Net → Client` 참조는 허용하지만, **Client의 public 멤버 중 §5 표에 적힌 것만** 사용한다. 그 밖의 멤버는 클라가 언제든 바꿀 수 있다.
- 권장: D1에 asmdef 3개(`VaroGO.Shared`, `VaroGO.Client`, `VaroGO.Net`)를 만들어 위 방향을 **컴파일 단계에서 강제**한다. `VaroGO.Client.asmdef`에는 Fusion 참조를 넣지 않는다.

## 2. 서비스 등록 (`GameServices`)

| 항목 | 규칙 |
| --- | --- |
| 호출자 | 오프라인: `OfflineBootstrap`(클라) / 온라인: `NetBootstrap`(서버). **한 실행에서 한 쪽만** 호출한다 |
| 온라인 호출 시점 | **`00_Boot`에서 `StartGame` 성공 직후, 코스 씬을 로드하기 전.** 이 시점엔 역할이 아직 `None`일 수 있다(§3.1에서 허용). 코스 씬의 `OfflineBootstrap`(Awake, 실행 순서 -1000)은 이미 온라인 등록이 있으면 아무것도 하지 않는다 |
| 오프라인 호출 시점 | 코스 씬 `OfflineBootstrap.Awake`. 에디터에서 코스 씬을 바로 실행하면 오프라인으로 동작한다 |
| 늦은 등록 방어 | 그래도 순서가 꼬일 경우를 대비해 `NetPlayer`는 `Spawned`에서 `SetLocal(HasStateAuthority)`를 **항상 다시 호출**한다(`OfflinePlayerDriver`가 먼저 `SetLocal(true)`를 불렀어도 덮어씀) |
| 씬에 배치된 Player | 코스 씬에는 오프라인용 `Player`가 직접 배치돼 있다. **온라인이면 `OfflineBootstrap`이 이 Player를 비활성화한다**(클라 담당). 서버는 씬의 Player를 건드리지 않고 `Player_Net`만 스폰한다 |
| 소비자 규칙 | `GameServices.Role != null`이면 바로 사용, 아니면 `Registered`를 구독해서 기다린다. 구독은 `OnDestroy` 또는 `OnDisable`에서 해제한다(구독한 쪽과 짝을 맞춘다: `Awake`↔`OnDestroy`, `OnEnable`↔`OnDisable`) |
| `Clock` 미등록 시 | 장애물은 움직이지 않고 시작 위치에 둔다(예외 금지) |
| `IsOnline` | `OfflinePlayerDriver`처럼 "온라인이면 스스로 꺼지는" 컴포넌트를 판단하는 용도로만 쓴다. 게임 규칙을 `IsOnline`으로 분기하지 않는다 |
| 재등록 | 씬 재시작(`Runner.LoadScene`) 시 다시 `Register`될 수 있다. 소비자는 `Registered`가 여러 번 와도 안전해야 한다 |

## 3. 인터페이스별 상세

### 3.1 `IRoleProvider` — 내 PC의 역할

| 항목 | 내용 |
| --- | --- |
| 구현 | 오프라인 `OfflineRoleProvider`(클라, F1=A / F2=B) · 온라인 `NetRoleProvider`(서버, Master=A) |
| 사용 | 클라: `MagicVisibility`, 스위치 요청자 값, 디버그 UI |
| 값 | 접속 직후 잠깐 `None`일 수 있다. `None`이면 **Common만 보이게** 처리한다 |
| 이벤트 | `LocalRoleChanged`는 값이 **실제로 바뀔 때만** 발생한다(같은 값 재설정 시 발생 안 함) |
| 서버 약속 | 역할은 한 세션 안에서 F9(디버그 스왑) 외에는 바뀌지 않는다. 두 PC는 항상 서로 다른 역할을 가진다 |

### 3.2 `IGameClock` — 공유 시계

| 항목 | 내용 |
| --- | --- |
| 구현 | 오프라인 `OfflineGameClock`(`Time.timeAsDouble`) · 온라인 `NetGameClock`(`Runner.SimulationTime` 기반) |
| 단위 | 초(double). **두 PC에서 같은 순간에 같은 값**(오차 ±1틱 허용) |
| 단조성 | 감소하지 않는다. 씬 재시작 시 0부터 다시 시작할 수 있다 |
| 클라 약속 | 장애물 위치는 **`f(Clock.Now)` 순수 함수**로만 계산한다. `+= deltaTime` 누적 상태 금지(오프셋 테스트로 검증: `OfflineGameClock.Offset`) |
| 서버 약속 | 장애물에 `NetworkTransform`·`NetworkObject`를 붙이지 않는다 |

### 3.3 `ISwitchState` — 스위치·발판·레버

| 항목 | 내용 |
| --- | --- |
| 구현 | 오프라인 `LocalSwitchState`(클라) · 온라인 `NetSwitchState`(서버). 둘 다 `ISwitchState` + `ISwitchDetails`를 구현한다 |
| 배치 | Net Variant에서 `NetSwitchState`를 `LocalSwitchState` **옆에 추가**한다(제거하지 않음). 온라인에서는 클라의 `SwitchStates.Resolve`가 `LocalSwitchState`가 아닌 구현체를 고른다. 오프라인에서는 `LocalSwitchState`를 고른다 |
| 설정값 | 설정값의 원본은 `LocalSwitchState`의 Inspector 값 하나뿐이다. `NetSwitchState`는 같은 GameObject의 `LocalSwitchState`에서 `AllowedRole`, `AutoOffSeconds`, `StartOn`을 읽는다(자기 필드를 따로 두지 않음 → 값 이중 관리 없음) |
| Spawned 전 | `NetSwitchState`는 `Spawned` 전에 `IsOn`을 물으면 `StartOn`을 돌려준다(`[Networked]` 값에 접근하지 않는다. 접근 안전성 **확인 필요**) |
| `RequestSet` 호출자 | 클라의 상호작용 트리거. **로컬 플레이어(`PlayerController.IsLocal == true`)가 닿았을 때만** 호출한다. 원격 플레이어의 콜라이더는 무시 |
| `requester` 값 | 항상 `GameServices.Role.LocalRole` |
| 비동기 | `RequestSet` 직후 `IsOn`이 바뀌어 있다고 **가정하지 않는다**. 결과는 `Changed`로만 받는다(온라인은 RPC 왕복 후 반영) |
| 권한 검사 | 구현체가 한다(`allowedRole`). 거절되면 아무 일도 없다(이벤트 없음) |
| `Changed` | **구독자가 관찰할 수 있는 `IsOn` 값이 바뀔 때마다**, 모든 PC에서 발생한다. 처음부터 같은 값이면 발생하지 않는다 → 구독자는 구독 직후 `IsOn`을 한 번 읽어 반영한다. 늦게 들어온 PC에서 `Spawned` 때 받은 값이 `StartOn`과 다르면 `Changed`를 1회 발생시킨다 |
| 자동 꺼짐 | `autoOffSeconds` 타이머는 구현체가 관리한다(온라인: `TickTimer`). 클라는 타이머를 따로 돌리지 않는다 |
| 참조 방법 | 문·발판은 스위치를 **GameObject로 참조**(`stateObject`)하고 `SwitchStates.Resolve`로 얻는다. 컴포넌트 타입(`LocalSwitchState`)을 직접 참조하지 않는다 |
| 재시작 | 켜진 상태에서 다시 켜면 `LastOnTime`만 갱신(자동 꺼짐 타이머 재시작). 오프라인·온라인 동일 |

### 3.4 `IGoalState` — 골

| 항목 | 내용 |
| --- | --- |
| 구현 | 오프라인 `LocalGoalState`(클라) · 온라인 `NetGoalState`(서버) |
| 배치 | 스위치와 같은 "추가만" 방식. Net Variant에서 `LocalGoalState` 옆에 `NetGoalState`를 추가한다. 클라는 온라인이면 `LocalGoalState`가 아닌 구현체, 오프라인이면 `LocalGoalState`를 고른다 |
| `ReportInGoal` 호출자 | 클라의 골 트리거. **로컬 플레이어의 진입/이탈만** 보고한다(각 PC가 자기 역할만 보고 → 중복 없음) |
| 오프라인 테스트 | F1/F2로 역할을 바꿔 가며 양쪽 진입을 흉내 낸다 |
| `ChapterCleared` | 두 역할이 동시에 안에 있을 때 **한 번만**, 모든 PC에서 발생 |
| 재시작 | 클리어 연출 뒤 씬 재시작은 서버 담당(`Runner.LoadScene`). 클라는 연출만 한다 |

### 3.5 `IPlayerSimulation` — 플레이어 ↔ 네트워크 래퍼

| 항목 | 내용 |
| --- | --- |
| 구현 | `PlayerController`(클라) |
| 호출자 | 오프라인 `OfflinePlayerDriver`(클라) · 온라인 `NetPlayer`(서버) |
| `SetLocal(true)` | 내 캐릭터. 입력·카메라·`Simulate`가 켜진다 |
| `SetLocal(false)` | 원격 캐릭터. 입력·카메라·이동 계산을 끈다. **콜라이더는 켜 둔다**(밀기·충돌 판정용). 위치는 서버(`NetworkTransform`)가 덮어쓴다 |
| 호출 순서 | `SetLocal`은 `Simulate`보다 먼저 정확히 한 번(온라인: `Spawned`에서) |
| `Simulate(dt)` | 로컬 플레이어에게만, 온라인은 `FixedUpdateNetwork`에서 `Runner.DeltaTime`으로 호출. 클라는 **`Simulate` 안에서 `Time.deltaTime`을 읽지 않는다**. 입력은 `Update`에서 버퍼에 쌓고 `Simulate`에서 소비한다 |
| 순간이동 | 부활·체크포인트 이동은 반드시 `PlayerController.Teleport(pos, rot)`로 한다. `transform.position` 직접 대입 금지. `Teleport`가 `Teleported`를 발생시키고, 서버는 이를 받아 `NetworkTransform.Teleport`로 보간을 끊는다 |
| `EventRaised` | 두 경로로 발생한다. ① 로컬 플레이어: 자기 시뮬레이션에서 ② 원격 플레이어: `PlayRemoteEvent(e)`가 호출됐을 때. 클라의 이펙트·사운드(`PlayerReactionFx`)는 이 이벤트 하나만 구독하므로 로컬·원격이 같은 연출을 낸다 |
| 원격 전달 경로 | 로컬 PC `EventRaised` → `NetPlayer`가 **State Authority일 때만** RPC 전송 → 상대 PC의 `NetPlayer`가 `PlayRemoteEvent(e)` 호출. 원격 쪽에서 발생한 `EventRaised`를 다시 RPC로 보내면 무한 반복되므로 금지 |
| `PlayRemoteEvent` | 로컬 플레이어에게 호출되면 무시된다. `Jumped`를 받으면 원격 Animator의 `Jump` 트리거도 재생한다 |
| 넉백·사망 판정 | 맞은 사람의 PC에서 로컬로 판정한다. 서버는 판정·검증하지 않는다 |

## 4. 절대 규칙 (어기면 바로 버그)

| # | 규칙 | 이유 |
| --- | --- | --- |

| R8 | Net Variant는 원본 컴포넌트를 **추가만** 하고 제거·값 변경하지 않는다. 스위치 설정값은 `LocalSwitchState` 한 곳에만 둔다 | 원본 수정이 Variant에 그대로 반영되게 / 값 이중 관리 방지 |

## 5. 서버가 써도 되는 클라 public 멤버 (화이트리스트)

이 표에 없는 클라 멤버는 서버가 쓰지 않는다. 클라는 이 표의 멤버를 바꾸거나 지우기 전에 §8 절차를 따른다.

| 타입 | 멤버 | 용도 |
| --- | --- | --- |
| `PlayerController` | `IPlayerSimulation` 전체 | 구동 |
| `PlayerController` | `IsLocal`, `IsGrounded` | 디버그 오버레이(F10) |
| `PlayerController` | `Teleport(Vector3, Quaternion)` | 서버 주도 스폰 위치 지정 |
| `LocalSwitchState` | `AllowedRole`, `AutoOffSeconds`, `StartOn` (읽기 전용) | `NetSwitchState`의 설정값 |
| `Animator` 파라미터 | `Speed`(float), `Grounded`(bool), `Airborne`(bool) | `NetworkMecanimAnimator` 동기화 대상 |
| `Animator` 트리거 | `Jump` | **동기화하지 않는다.** 원격은 `PlayerEvent.Jumped` → `PlayRemoteEvent`로 재생 |

> **Animator 트리거**: `NetworkMecanimAnimator`는 일반 `animator.SetTrigger` 호출을 원격에 자동으로 보내지 않을 수 있다(Fusion 2 문서로 D2에 확인). 그래서 v0.2부터 트리거는 이벤트로 재생한다. 서버는 `NetworkMecanimAnimator`에서 트리거 동기화를 켜지 않는다(이중 재생 방지).

| 원본 (클라 소유) | Variant (서버 소유) | Variant에서 허용 | Variant에서 금지 |
| --- | --- | --- | --- |
경로 기준: `Assets/02_Prefabs/`

| 원본 (클라 소유) | Variant (서버 소유) | Variant에서 허용 | Variant에서 금지 |
| --- | --- | --- | --- |
| `Client/Player.prefab` | `Net/Player_Net.prefab` | `NetworkObject`, `NetworkTransform`, `NetworkMecanimAnimator`, `NetPlayer` 추가 | 클라 컴포넌트 값 수정·제거, 자식 구조 변경 |
| `Client/Level/Switches/Lever_*`, `PressurePlate_*` | `Net/Level/Switches/<원본이름>_Net.prefab` | 루트에 `NetworkObject` 추가, `LocalSwitchState`가 있는 GameObject에 `NetSwitchState` **추가** | `LocalSwitchState` 제거, 트리거·비주얼 수정 |
| `Client/Level/Switches/Set_*` | `Net/Level/Switches/Set_*_Net.prefab` | **Set 루트에만** `NetworkObject` 추가, 중첩된 레버/발판의 `LocalSwitchState` 옆에 `NetSwitchState` 추가 | 중첩 인스턴스 안에 `NetworkObject` 추가(중첩 NetworkObject 회피), 중첩 컴포넌트 제거 |
| `Client/Level/Switches/Door`, `TimedPlatform` | **Variant 없음** | — | 상태가 없고 스위치를 구독만 한다 |
| `Client/Level/Progress/Goal.prefab` | `Net/Level/Progress/Goal_Net.prefab` | `NetworkObject` 추가, `LocalGoalState` 옆에 `NetGoalState` **추가** (`LocalGoalState` 제거 금지) | 트리거 크기 수정 |
| `Client/Level/Progress/Checkpoint`, `KillZone` | **Variant 없음** | — | 각 PC에서 로컬 판정 |
| `Client/Level/Obstacles/*`, `Client/Level/Magic/*` | **Variant 없음** | — | 네트워크 컴포넌트 추가(R2, R3) |

- `Set_*` 프리팹은 스위치와 문이 묶인 세트다. `NetworkBehaviour`는 부모의 `NetworkObject`에 묶이므로 루트 하나로 충분하다(동작 **확인 필요**: 자식 GameObject의 NetworkBehaviour가 루트 NetworkObject에 등록되는지).
- 한 Set 안에 스위치가 여러 개여도 `NetworkObject`는 루트 하나, `NetSwitchState`는 스위치마다 하나.
- 전체 목록과 조절값은 `Assets/05_Docs/00_공통/현재_프리팹_리스트.md` 참고.

- 클라가 원본 프리팹의 **컴포넌트를 추가·제거·이름 변경**하면 메신저로 알린다(값 조정은 알릴 필요 없음).
- `OfflinePlayerDriver`는 `IsOnline`이면 스스로 꺼지므로 Variant에서 지우지 않는다.

## 8. 계약 변경 절차

| 변경 종류 | 예 | 절차 |
| --- | --- | --- |
| **추가** (깨지지 않음) | 새 인터페이스, enum 맨 뒤 값, 새 이벤트 | 제안자가 `Shared`만 수정한 작은 커밋 → 메신저 공유 → 상대 확인 후 `develop`에 merge |
| **변경·삭제** (깨짐) | 메서드 시그니처, 이름, 의미 변경 | 둘이 합의 → **같은 날** 양쪽 구현까지 고쳐서 `develop`에 merge. 합의 전에는 각자 브랜치에서 `Shared`를 고치지 않는다 |
| **규칙만 변경** | 이 문서의 표 수정 | 문서 수정 커밋 + 메신저 공유 |

- `Shared` 수정 커밋 메시지는 `contract:`로 시작한다(예: `contract: add PlayerEvent.Jumped`).
- 변경할 때마다 §10 변경 기록에 한 줄 추가하고 문서 버전을 올린다.
- 자기 브랜치에서 `Shared`를 급하게 바꿔야 하면, **그 커밋만 따로** 만들어 상대가 cherry-pick 할 수 있게 한다.
