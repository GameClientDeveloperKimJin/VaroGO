# 성능 측정 계획 — 스테이지1

최종 갱신: 2026-11-25

## 1. 목표

- **60 FPS 유지** = 한 프레임을 16.6ms 안에 그려야 한다.
- 이 PC(아래)에서 여유 있게 돌고, **이 PC보다 낮은 사양에서도** 60 FPS에 가깝게 나오게 한다.
- 목표치(이 PC, 빌드 기준): 평균 프레임 시간 **10ms 이하**(여유 40%), 33ms 넘는 끊김 **0회**, 로딩 중 5초 넘는 멈춤 **0회**.

측정 PC: i5-10400F(6코어 12스레드) · RTX 2060 SUPER(VRAM 8GB) · RAM 32GB · Windows 11 · Unity 6.3 · URP(PC 품질) · DX12

## 2. 1차 측정 결과 (기준값)

측정일 2026-11-25, **에디터 2개 동시 실행(메인 + MPPM 클론), 온라인 2인 접속** 상태.
같은 PC에서 화면 2개를 그리고 있어서 숫자가 실제보다 나쁘게 나온다. 개선 전후를 **같은 조건에서 비교하는 기준값**으로 쓴다.

### 2-4. 메모리 쓰레기(GC 할당)

- 스테이지1: **초당 1.2~2MB** (프레임마다 약 50KB씩 계속 생김) → 쌓였다가 한꺼번에 치우면서 끊김이 생길 수 있다.

**읽는 법**
- GPU 비용의 대부분은 **그림자를 화면에서 부드럽게 거르는 일(픽셀 단위)**이다. 그림자를 드리우는 물체 수·그림자 거리·캐스케이드를 줄여도 거의 줄지 않는다. 2-5절에서 물체를 통째로 숨겼을 때 크게 줄던 것은 그림자가 아니라 그 물체 자체를 그리는 비용이었다.
- SSAO는 "깊이만 사용"(물체를 한 번 더 그리는 노멀 프리패스 제거)이 가장 효율적이다(Z2 −2.2ms).
- 장식 그림자 끄기와 그림자 거리는 **효과가 없으니 하지 않는다**. 풀 장식 거리와 LOD bias는 Z0에서만 조금 효과가 있다.

## 5. 반복 측정 절차 (개선할 때마다 똑같이)

1. 에디터를 켠 뒤 **한 번 미리 순회**(셰이더 준비 상태를 같게 맞춤). 첫 방문 끊김을 재는 회차만 따로 표시한다.
2. Scene 창은 닫거나 다른 탭 뒤로 둔다(Scene 창도 그리면 숫자가 섞임). Game 창 크기는 1920x1080으로 고정한다.
3. 외부 기록기를 켠다 → 메인 Play → Game 창 클릭 → 손 떼기.
4. 끝나면(`측정 끝` 로그) Play를 멈추고 CSV를 집계한다: 구역별 평균 FPS·프레임 시간·33ms 끊김 수·드로우콜·삼각형·GC, 구간별 GPU 사용률·VRAM.
5. 바꾼 것 한 가지 → 같은 절차로 다시 측정 → 위 2장 표와 비교해 기록한다.
