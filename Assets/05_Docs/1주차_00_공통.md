## 1. 1주차 목표

GDD 13.1의 질문 하나만 검증한다.

> **"서로 다른 장애물을 보는 두 사람이 실제로 대화하고, 웃고, 협동하는 과정이 재미있는가?"**

### 1.1 완료 기준 (금요일 기준)

- [ ] 서로 다른 PC 2대가 **세션 코드**로 같은 방에 접속한다.
- [ ] A는 붉은 오브젝트만, B는 푸른 오브젝트만 보인다. 보이지 않아도 충돌은 공통이다.
- [ ] 데모 룸 1개를 두 사람이 처음부터 끝까지 클리어한다(5개 구간, 2.3 참고).
- [ ] 움직이는 장애물에 맞으면 밀리거나 날아가고, 떨어지면 개인 부활한다.
- [ ] 내부 플레이테스트 2회를 진행하고 7장 체크리스트를 기록한다.
- [ ] 데모 영상(양쪽 화면 동시 녹화)을 1회 이상 촬영한다.

## 2. 기술 결정 요약

| 항목 | 결정 | 비고 |
| --- | --- | --- |
| 엔진 | Unity 6000.3.4f1, URP | 현재 프로젝트 |
| 네트워크 | **Photon Fusion 2 — Shared Mode** | 각자 자기 캐릭터의 State Authority를 가짐 |
| 씬 오브젝트 권한 | Master Client가 소유 | 스위치, 문, 골 상태 |
| 플레이어 이동 | 로컬 시뮬레이션 + `NetworkTransform` | 조작감 우선 |
| 이동 장애물 | **공유 시계 기반 결정적 움직임** | 위치 동기화 없음 |
| 넉백 판정 | **피격자 로컬 판정** | 내 화면 기준으로 맞으면 날아감 |
| 비대칭 시야 | 로컬 Renderer on/off, Collider는 항상 on | 동기화 대상 아님 |
| 캐릭터 컨트롤러 | Unity `CharacterController` 기반 자체 구현 | 넉백 커스터마이징이 자유로움. 클라 코드가 Fusion에 의존하지 않음 |
| 입력 | Input System (키보드+마우스, 게임패드) | 이미 설치됨 |
| 카메라 | Cinemachine 3.x | 클라이언트가 설치 |
| 접속 방식 | 6자리 세션 코드 입력 | Steam 친구 초대는 2주차 이후 |
| 음성 | 디스코드로 대체 | 인게임 음성은 1주차 범위 밖 |
| 최종 플랫폼 | Steam | 1주차 작업 없음 |

### 2.1 핵심 아이디어: 오프라인 우선 개발

- 클라이언트는 **네트워크 없이 혼자서** 모든 게임플레이를 만든다. 역할(A/B)은 디버그 키로 바꾼다.
- 서버는 같은 기능을 **인터페이스 구현체만 바꿔서** 온라인으로 연결한다.
- 그래서 1일차에 공통 계약(4장)을 반드시 확정해야 둘이 서로를 기다리지 않는다.

### 2.2 데모 룸 구성 (기획자와 함께 확정)

| 구간 | 내용 | 검증하려는 재미 |
| --- | --- | --- |
| 1. 튜토리얼 | 붉은 발판(A만 보임)·푸른 발판(B만 보임)이 번갈아 놓인 짧은 다리 | 규칙 학습, 안 보이는 발판도 밟힌다는 발견 |
| 2. 안내 점프 | B만 보이는 발판으로 A가 건너야 함 | B가 안내자, A가 행동자 |
| 3. 투명 벽 미로 | A만 보이는 벽 미로를 B가 통과 | **역할 교대** |
| 4. 스위치 분리 경로 | 분리된 길. A 전용 스위치가 B 쪽 문을 열고, 그 반대도 마찬가지. 시간제한 발판 1개 | 분리·합류, 타이밍 공유 |
| 5. 해머 구간 | 회전 해머, 밀어내는 벽 → 골 | 상황 코미디, 넉백 |

## 3. 작업 규칙

### 3.1 브랜치

| 브랜치 | 용도 |
| --- | --- |
| `main` | 플레이테스트를 통과한 빌드만 |
| `develop` | 통합 브랜치. **D2부터 매일 저녁 여기로 합친다** |
| `Client---System_Content` | 클라이언트 작업 |
| `Server---Network` | 서버 작업 |

- 공통 계약(`03_Scripts/Shared`)은 D1 오전에 둘이 같이 작성하고, **`develop`에 먼저 합친 뒤** 각자 브랜치로 가져간다.
- 매일 아침 `develop`을 자기 브랜치에 merge한 뒤 작업을 시작한다.

### 3.2 폴더

```
Assets/
  01_Scenes/      00_Boot.unity (서버), 10_DemoRoom.unity (클라)
  02_Prefabs/
    Client/       원본 프리팹 (클라 소유)
    Net/          네트워크 Prefab Variant (서버 소유)
  03_Scripts/
    Shared/       공통 계약 — 둘이 합의해야 수정 가능
    Client/       namespace VaroGO.Client
    Server/       namespace VaroGO.Net
  04_Resources/
  05_Docs/
```

### 3.3 씬·프리팹 소유권 (충돌 방지)

| 에셋 | 소유자 | 규칙 |
| --- | --- | --- |
| `10_DemoRoom.unity` | 클라 | 서버는 D3 통합 때만 수정하고, 수정 전에 메신저로 **"DemoRoom 잠금"**을 알린다 |
| `00_Boot.unity` | 서버 | 클라는 수정하지 않는다 |
| `02_Prefabs/Client/*` | 클라 | 원본 프리팹 |
| `02_Prefabs/Net/*_Net` | 서버 | 원본의 **Prefab Variant**. 원본이 바뀌면 자동으로 반영된다 |
| `03_Scripts/Shared/*` | 공동 | PR이나 메신저로 합의한 뒤 수정 |

- **Unity 씬 파일은 merge하지 않는다.** 같은 씬을 둘이 동시에 수정하지 않는다.
- 프로젝트 설정(`ProjectSettings/`) 변경은 메신저로 공유한다(특히 Physics, Layer, Tag).

### 3.4 레이어·태그 (D1에 클라가 등록)

| 이름 | 종류 | 용도 |
| --- | --- | --- |
| `Player` | Layer | 플레이어 캐릭터 |
| `Ground` | Layer | 밟을 수 있는 지형 |
| `Magic` | Layer | 마법 오브젝트(충돌은 있음) |
| `Obstacle` | Layer | 움직이는 장애물 |
| `KillZone` | Tag | 낙사 영역 |

## 4. 공통 계약 (D1 오전, 둘이 같이 작성)

파일: `Assets/03_Scripts/Shared/Contracts.cs`

```csharp
using System;
using UnityEngine;

namespace VaroGO.Shared
{
    public enum PlayerRole { None = 0, A_Red = 1, B_Blue = 2 }

    // 오브젝트를 누가 볼 수 있는가. 충돌은 항상 공통.
    public enum MagicType { Common = 0, Red = 1, Blue = 2 }

    public enum PlayerEvent { Died, Respawned, KnockbackLight, KnockbackHeavy, Landed, HitInvisible }

    // 내 PC의 역할. 오프라인: 디버그 키로 전환 / 온라인: 서버가 배정
    public interface IRoleProvider
    {
        PlayerRole LocalRole { get; }
        event Action<PlayerRole> LocalRoleChanged;
    }

    // 두 PC에서 같은 값이 나와야 하는 시간(초). 이동 장애물은 이 값만 사용한다.
    public interface IGameClock
    {
        double Now { get; }
    }

    // 스위치·발판·레버의 on/off 상태. 문과 시간제한 발판은 Changed를 구독한다.
    // 구현체 공통 직렬화 필드: PlayerRole allowedRole (None = 둘 다 가능),
    //                         float autoOffSeconds (0 = 계속 유지), bool startOn
    public interface ISwitchState
    {
        bool IsOn { get; }
        event Action<bool> Changed;
        void RequestSet(bool on, PlayerRole requester); // 권한 검사는 구현체가 한다
    }

    // 골 지점. 두 역할이 모두 들어오면 ChapterCleared가 발생한다.
    public interface IGoalState
    {
        bool IsCleared { get; }
        event Action ChapterCleared;
        void ReportInGoal(PlayerRole role, bool inside);
    }

    // 플레이어 캐릭터(클라 구현) ↔ 네트워크 래퍼(서버 구현) 사이의 계약
    public interface IPlayerSimulation
    {
        void SetLocal(bool isLocal);       // false: 입력·카메라·시뮬레이션 끔(원격 플레이어)
        void Simulate(float deltaTime);    // 로컬 플레이어에게만 호출된다
        event Action<Vector3> Teleported;  // 부활 등 순간이동. 네트워크 보간을 끊는 데 사용
        event Action<PlayerEvent> EventRaised; // 원격 이펙트·사운드 재생용
    }

    // 전역 서비스 등록소. 오프라인/온라인 부트스트랩이 Register를 호출한다.
    public static class GameServices
    {
        public static IRoleProvider Role { get; private set; }
        public static IGameClock Clock { get; private set; }
        public static bool IsOnline { get; private set; }
        public static event Action Registered;

        public static void Register(IRoleProvider role, IGameClock clock, bool isOnline)
        {
            Role = role;
            Clock = clock;
            IsOnline = isOnline;
            Registered?.Invoke();
        }
    }
}
```

### 4.1 구현 담당

| 계약 | 오프라인 구현 (클라) | 온라인 구현 (서버) |
| --- | --- | --- |
| `IRoleProvider` | `OfflineRoleProvider` — F1=A, F2=B | `NetRoleProvider` |
| `IGameClock` | `OfflineGameClock` — `Time.timeAsDouble` | `NetGameClock` — `Runner.SimulationTime` |
| `ISwitchState` | `LocalSwitchState` | `NetSwitchState` |
| `IGoalState` | `LocalGoalState` | `NetGoalState` |
| `IPlayerSimulation` | `PlayerController` (구현체) + `OfflinePlayerDriver` | `NetPlayer` (호출자) |

### 4.2 D3 이후 테스트 방법

D3 통합 뒤에는 데모 룸에 Fusion `NetworkObject`가 들어간다. 그래서 혼자 테스트할 때도 **`00_Boot`의 "Solo" 버튼(Fusion `GameMode.Single`)**으로 실행한다. 클라는 원본 프리팹만 있는 별도 씬(`11_DemoRoom_Offline`)을 계속 유지해도 된다.

### 5.1 통합 체크리스트 (매 통합마다)

- [ ] 두 사람 모두 `develop`을 merge한 뒤 컴파일 에러가 없다.
- [ ] `00_Boot` → 세션 생성 → 다른 PC에서 코드로 입장 → 데모 룸이 로드된다.
- [ ] 콘솔에 Error, Exception이 없다.
- [ ] Windows 빌드를 만들어 공유 폴더에 올린다(`Builds/YYMMDD_HHmm/`).

## 6. 1주차 범위 밖 (하지 않는다)

- Steam 연동(초대, 인증, 업적), 랜덤 매칭, 재접속, 인게임 음성 채팅
- 스토리, 컷신, NPC, 히든 아이템, 엔딩
- 최종 아트, 애니메이션 폴리싱(그레이박스와 기본 캐릭터로 충분)
- 저장, 옵션 메뉴, 키 리바인딩
- 최적화

> 아트 담당은 이 기간에 **붉은/푸른 마법 머티리얼 + 색 이외의 구분 문양**(GDD 12.2)을 먼저 만들어 주면 D4 그레이박스에 바로 적용할 수 있다.
