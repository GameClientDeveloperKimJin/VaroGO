# 1주차 작업지시서 — 02. 서버(네트워크)

**담당:** 서버(네트워크) 개발자  
**브랜치:** `Server---Network`  
**네임스페이스:** `VaroGO.Net`  
**선행 문서:** `1주차_00_공통.md` (공통 계약, 브랜치·소유권 규칙)

> **한 줄 요약:** 클라이언트가 만든 오프라인 게임플레이를 **Photon Fusion 2 Shared Mode**로 두 사람이 함께 플레이할 수 있게 만든다. 매일 빌드해서 PC 2대로 테스트하는 파이프라인도 서버 담당이 책임진다.

---

## 0. 원칙

1. **클라 코드는 수정하지 않는다.** 공통 계약(`VaroGO.Shared`) 인터페이스를 구현하거나 호출해서 연결한다. 클라 코드 수정이 필요하면 요청한다.
2. **동기화는 최소로 한다.** 비대칭 시야와 이동 장애물은 동기화하지 않는다(각자 로컬에서 계산).
3. **프리팹은 Variant로 만든다.** 클라 원본(`02_Prefabs/Client`)을 직접 수정하지 않고, `02_Prefabs/Net/*_Net` Variant에 네트워크 컴포넌트를 붙인다.
4. **매일 PC 2대로 테스트한다.** 에디터 2개로 하는 테스트만으로는 충분하지 않다.

### 0.1 동기화 대상 정리 (GDD 11.2 대응)

| GDD 11.2 항목 | 1주차 처리 방식 |
| --- | --- |
| 플레이어 위치·이동·점프·충돌 | 각자 State Authority. `NetworkTransform` + `NetworkMecanimAnimator` |
| 이동형 장애물 위치·속도 | **동기화 안 함.** `NetGameClock`으로 각자 계산 |
| 넉백·날아감·착지·사망·부활 | 피격자 로컬 처리. 결과 위치는 `NetworkTransform`, 연출 이벤트는 RPC(P1) |
| 스위치·오브젝트 상호작용 | `NetSwitchState` — Master Client 소유 `[Networked]` |
| 시간제한 퍼즐 활성화 | `NetSwitchState`의 `TickTimer` |
| 퍼즐 완료·챕터 진행 | `NetGoalState` |
| 플레이어별 가시성 | **동기화 안 함.** 역할만 동기화하면 각자 로컬에서 처리 |

### S-02. Fusion 2 설치·설정

- Photon Fusion 2 최신 안정 버전(2.0.x)을 설치한다. **팀 전원이 같은 버전을 쓴다.** 버전을 `05_Docs/기술스택.md`에 기록한다.
- Photon Dashboard에서 Fusion App을 만들고 App ID를 `PhotonAppSettings`에 넣는다.
  - 저장소가 공개 저장소라면 App ID를 커밋하지 않는다(팀 내 공유 방법을 정한다).
- **Fixed Region = `kr`** (테스트 중 핑을 안정시키기 위해)
- `NetworkProjectConfig`
  - Tick Rate: 60 (기본값)
  - Physics: Unity 물리(장애물의 Kinematic Rigidbody, CharacterController)가 Fusion 실행 중에도 정상으로 동작하는지 확인한다. Fusion이 물리 시뮬레이션 모드를 바꾸는지, `RunnerSimulatePhysics3D`가 필요한지 D1에 검증해서 결과를 기록한다.
- Unity 6 **Multiplayer Play Mode**(`com.unity.multiplayer.playmode`)를 설치해서 에디터 안에서 가상 플레이어 2명으로 테스트할 수 있게 한다.
- Unity 6000.3과 Fusion 2의 호환성 문제가 있으면 즉시 공유한다.

**완료 조건**
- [ ] Fusion 샘플 없이 빈 씬에서 `NetworkRunner`가 Shared Mode로 접속되고 `kr` 리전으로 연결된다.
- [ ] Multiplayer Play Mode로 플레이어 2명이 같은 세션에 들어간다.

### S-04. `NetBootstrap`

- `NetworkRunner`를 생성하고 `StartGame`을 호출한다.
  ```csharp
  var result = await runner.StartGame(new StartGameArgs
  {
      GameMode = GameMode.Shared,          // Solo는 GameMode.Single
      SessionName = code,
      PlayerCount = 2,
      IsVisible = false,
      Scene = SceneRef.FromIndex(demoRoomBuildIndex),
      SceneManager = runner.gameObject.AddComponent<NetworkSceneManagerDefault>(),
  });
  ```
- 씬 로드가 끝나면 `GameServices.Register(netRole, netClock, isOnline: true)`를 호출한다.
  - 클라의 `OfflineBootstrap`은 `IsOnline == true`이면 아무것도 하지 않는다. **등록 순서**(Net이 먼저 등록되는지)를 D2 통합에서 꼭 확인한다.
- 세션이 끝나거나 실패하면 `00_Boot`로 돌아가고 `GameServices`를 초기화한다.

### S-05. 플레이어 스폰·`NetPlayer`

- `02_Prefabs/Net/Player_Net` = 클라의 `Player.prefab` **Variant**
  - 추가 컴포넌트: `NetworkObject`, `NetworkTransform`, `NetworkMecanimAnimator`, `NetPlayer`
- 스폰: Shared Mode에서는 **각자 자기 플레이어를 스폰한다.**
  ```csharp
  public class PlayerSpawner : SimulationBehaviour, IPlayerJoined
  {
      public void PlayerJoined(PlayerRef player)
      {
          if (player == Runner.LocalPlayer)
              Runner.Spawn(playerPrefab, spawnPoint.position, spawnPoint.rotation, player);
      }
  }
  ```
- `NetPlayer : NetworkBehaviour`
  - `Spawned()`: `IPlayerSimulation sim = GetComponent<IPlayerSimulation>()` → `sim.SetLocal(HasStateAuthority)`
  - `FixedUpdateNetwork()`: `if (HasStateAuthority) sim.Simulate(Runner.DeltaTime)`
  - `sim.Teleported += pos => networkTransform.Teleport(pos)` — 부활할 때 원격 화면에서 보간되어 미끄러지는 현상을 막는다.
- 스폰 위치: A와 B가 겹치지 않게 스폰 포인트를 2개 둔다.

**확인할 것**
- 원격 플레이어의 움직임이 끊기거나 떨리지 않는지 확인한다(`NetworkTransform` 보간 설정).
- 원격 플레이어의 `CharacterController`가 로컬 플레이어의 이동을 막는지 확인한다. 서로 밀거나 올라탈 수 있는 것은 코미디 요소이므로 **충돌은 유지하는 것을 기본으로** 하고, 문제가 크면 공유한다.

**완료 조건**
- [ ] PC 2대에서 서로의 캐릭터가 움직이고, 걷기·점프 애니메이션이 보인다.
- [ ] 카메라는 각자 자기 캐릭터만 따라간다.
- [ ] 부활할 때 원격 화면에서 순간이동으로 보인다.

### S-06. 역할 배정·`NetRoleProvider`

- 규칙: **Master Client = A_Red, 나머지 = B_Blue**
- `NetPlayer`에 `[Networked] PlayerRole Role { get; set; }`
  - `Spawned()`에서 State Authority가 설정한다: `Role = Runner.IsSharedModeMasterClient ? PlayerRole.A_Red : PlayerRole.B_Blue`
- `NetRoleProvider : IRoleProvider` — 로컬 플레이어의 `Role`을 반환하고, 값이 바뀌면 `LocalRoleChanged`를 발생시킨다(`[OnChangedRender]` 또는 `ChangeDetector`).
- 디버그(Development Build 한정): **F9 = 두 사람의 역할 교환** — 같은 사람이 A와 B를 모두 경험하는 테스트용

**알려진 한계 (1주차 허용)**
- Master Client가 나갔다가 다시 들어오면 역할이 겹칠 수 있다. 1주차에는 S-12의 "세션 종료 → Boot로 복귀"로 처리한다.

**완료 조건**
- [ ] 방을 만든 사람은 붉은 오브젝트만, 참가한 사람은 푸른 오브젝트만 본다.
- [ ] F9를 누르면 두 PC의 시야가 동시에 바뀐다.

### S-07. `NetGameClock`

- `IGameClock.Now` → `Runner.SimulationTime`
- 이동 장애물은 이 값으로만 움직이므로, **두 PC에서 같은 시각에 같은 위치에 있어야 한다.**
- 검증: 디버그 오버레이(S-13)에 `Now`를 표시하고, 두 PC 화면을 한 영상으로 녹화해서 해머 위치를 비교한다.
  - 차이가 크면(체감상 해머 위치가 눈에 띄게 다르면) Tick 기반 시간(`Runner.Tick * Runner.DeltaTime`)과 비교해서 더 일치하는 쪽을 채택하고 결과를 기록한다.

**완료 조건**
- [ ] 두 PC에서 해머의 위치가 눈으로 구분되지 않을 만큼 같다.
- [ ] 늦게 들어온 플레이어의 장애물도 처음부터 같은 위상으로 움직인다.

### S-08. `NetSwitchState`

- `NetSwitchState : NetworkBehaviour, ISwitchState`
  - 클라의 `LocalSwitchState`와 **같은 직렬화 필드**: `allowedRole`, `autoOffSeconds`, `startOn`
  - `[Networked, OnChangedRender(nameof(OnIsOnChanged))] NetworkBool IsOnNet { get; set; }`
  - `[Networked] TickTimer OffTimer { get; set; }`
  - `RequestSet(on, requester)` → `RPC_RequestSet(on, requester)`
  ```csharp
  [Rpc(RpcSources.All, RpcTargets.StateAuthority)]
  void RPC_RequestSet(NetworkBool on, PlayerRole requester)
  {
      if (allowedRole != PlayerRole.None && allowedRole != requester) return;
      IsOnNet = on;
      if (on && autoOffSeconds > 0)
          OffTimer = TickTimer.CreateFromSeconds(Runner, autoOffSeconds);
  }

  public override void FixedUpdateNetwork()
  {
      if (HasStateAuthority && OffTimer.Expired(Runner))
      {
          IsOnNet = false;
          OffTimer = TickTimer.None;
      }
  }
  ```
  - `OnIsOnChanged()` → `Changed?.Invoke(IsOnNet)`
  - `Spawned()`에서 현재 값으로 `Changed`를 한 번 발생시킨다(늦게 들어온 플레이어의 문 상태 맞추기).
- 씬 오브젝트이므로 State Authority는 Master Client에게 있다. `NetworkObject`에 **Is Master Client Object** 옵션을 켜서, Master Client가 바뀌면 권한이 넘어가게 한다.
- D3 오후에 클라에게 프리팹을 받아 `_Net` Variant를 만든다: `LocalSwitchState`를 제거하고 `NetworkObject` + `NetSwitchState`를 추가한 뒤, 연출 컴포넌트의 `stateSource`를 다시 연결한다.
- D3 저녁에 **"DemoRoom 잠금"**을 알리고 씬의 스위치를 `_Net` Variant로 교체한다.

**완료 조건**
- [ ] A가 스위치를 누르면 B 화면의 문이 열린다(그 반대도 동일).
- [ ] 권한이 없는 역할이 누르면 상태가 바뀌지 않는다.
- [ ] 시간제한 발판이 두 PC에서 같은 시점에 꺼진다.

### S-09. `NetGoalState`·클리어·재시작

- `NetGoalState : NetworkBehaviour, IGoalState`
  - `[Networked] NetworkBool AInGoal`, `BInGoal`, `Cleared`
  - `ReportInGoal(role, inside)` → RPC → StateAuthority가 값을 갱신하고, 둘 다 true이면 `Cleared = true`
  - `Cleared`가 바뀌면 → `ChapterCleared` 발생 → 클라의 클리어 UI가 표시된다
- 재시작(R 키): 아무나 누르면 Master Client가 `Runner.LoadScene`으로 데모 룸을 다시 로드한다.

**완료 조건**
- [ ] 한 명만 골에 들어가면 클리어되지 않는다.
- [ ] 둘 다 들어가면 두 PC에서 동시에 "CLEAR!"가 나온다.
- [ ] R을 누르면 두 PC 모두 처음부터 다시 시작한다.

### S-14. Steam 연동 사전 조사 (P2, 시간이 남으면)

2주차 이후 작업을 위해 조사만 하고 결과를 `05_Docs/Steam연동_조사.md`에 정리한다. **1주차 빌드에는 넣지 않는다.**

- Steamworks.NET 설치, 테스트 AppID 480(Spacewar)으로 초기화 확인
