# VAROGO 아트 제작 계약 v1.0

> 최종 갱신: 2026-11-04
> 대상: 아트 팀장(Claude), 검토자(KJ)
> 도구: VARCO 3D (플로우 "VARGO GO") → Unity

이 문서는 **오브젝트 아트를 어떤 순서로 만들고, 어디서 검토받는지**를 정한다.
검토 3번을 통과해야 다음 단계로 넘어간다. **승인 없이 다음 단계를 돌리지 않는다.**

---

## 1. 역할

| 담당 | 하는 일 |
| --- | --- |
| **아트 팀장 (Claude)** | 요청을 받아 이미지 → 모델 → 애니메이션을 만들고, 단계마다 검토를 요청한다. 끝나면 오브젝트 세션에 완료를 알린다. |
| **오브젝트 세션** (`개발_클라이언트_상호작용 오브젝트 및 기믹 오브젝트`) | 완료 알림을 받으면 실제 프리팹에 적용하고 프리팹 리스트를 갱신한다. |
| **검토자 (KJ)** | 단계마다 승인 / 수정 / 반려를 정한다. 오브젝트 요청(이름, 용도, 종류)을 준다. |

## 2. 공통 기준

- **스타일 참고 = `BG2_1.png` 하나** (키 아트). 모든 오브젝트가 이 그림을 따른다.
  - 카툰 3D, 둥글고 통통한 비율, 이끼 낀 돌, 볼트 박힌 나무
  - 색: 하늘색 · 주황빨강 · 이끼초록 · 따뜻한 갈색 · 크림
  - 마법 오브젝트: 빛나는 반투명 빨강 / 파랑
- **색 변형(공용 / 빨강 / 파랑)은 같은 모양에서 색만 바꾼다.** 모양이 같아야 충돌 판정·애니메이션을 같이 쓴다.
- **투명함은 Unity 머티리얼로 낸다.** VARCO 텍스처는 투명도를 담지 않는다.

## 3. 제작 순서와 검토 3번

```
요청 → ① 이미지 생성 → [검토 1] → ② 모델 생성 → [검토 2] → ③ 애니메이션 → [검토 3] → ④ 오브젝트 세션에 완료 알림 → 프리팹 적용 (오브젝트 세션)
```

### ① 이미지 생성 → 검토 1

| 항목 | 내용 |
| --- | --- |
| 만드는 것 | 오브젝트 그림 1장 + 필요한 색 변형 (흰 배경, 3/4 각도, 오브젝트만) |
| 보여 주는 것 | 이미지 전부, 사용 포인트, 다음 단계(모델) 예상 비용 |
| 검토 기준 | 키 아트와 어울리나 · 용도가 한눈에 보이나 (예: 밟는 곳이 넓은가) · 색 변형끼리 모양이 같은가 · **기본 모습(애니메이션 전 상태)인가** — 눌림·튕김 같은 동작 모습은 이미지에 넣지 않는다 |
| 승인 후 | 모델 생성으로 |

### ② 모델 생성 → 검토 2

| 항목 | 내용 |
| --- | --- |
| 만드는 것 | 승인된 이미지로 3D 모델. 색 변형은 같은 모델에 텍스처만 다시 입힌다 |
| 보여 주는 것 | Unity에 넣은 모습 스크린샷 (여러 각도, 플레이어 옆 크기 비교), 폴리곤 수, 사용 포인트 |
| 검토 기준 | 이미지와 같은 모양인가 · 뒷면·밑면이 깨지지 않았나 · 크기가 게임에 맞나 · 너무 무겁지 않나 |
| 승인 후 | 애니메이션으로 (애니메이션이 없는 오브젝트는 바로 프리팹 적용) |

### ③ 애니메이션 → 검토 3

| 항목 | 내용 |
| --- | --- |
| 만드는 것 | 요청된 움직임. 사람형이 아닌 오브젝트는 Unity에서 크기·위치·회전 변화로 만든다 (VARCO 애니메이션은 사람형 전용) |
| 보여 주는 것 | 동작 영상 또는 연속 스크린샷, 조절할 수 있는 값 (속도, 세기 등) |
| 검토 기준 | 의도한 느낌이 나나 · 너무 빠르거나 느리지 않나 · 게임 동작(점프, 충돌)과 맞나 |
| 승인 후 | ④ 완료 알림 |

### ④ 완료 알림 (검토 3 승인 후)

- 아트 팀장이 **`개발_클라이언트_상호작용 오브젝트 및 기믹 오브젝트` 세션에 직접 메시지로** 알린다. 문서로 남기는 게 아니라 세션끼리 통신으로 전한다.
- 내용: "제작 완료했으니 실제 프리팹에 적용해라" + 아래 정보
  - 오브젝트 이름, 색 변형 목록
  - 모델·머티리얼·애니메이션 파일 경로
  - 적용할 프리팹 (있으면 경로)
  - 조절할 수 있는 값 (애니메이션 속도·세기 등)
  - 주의할 점 (예: 투명 머티리얼, 색 변형은 같은 모델)
- 실제 프리팹 적용과 프리팹 리스트 갱신은 오브젝트 세션이 한다.
- 알림을 보내면 제작 기록 표에 "완료 알림 보냄"으로 적는다.

## 4. 검토 결과

| 결과 | 뜻 | 다음 |
| --- | --- | --- |
| **승인** | 그대로 OK | 다음 단계 |
| **수정** | 방향은 맞고 일부만 고침 | 같은 단계에서 고쳐 다시 검토 |
| **반려** | 방향이 틀림 | 이전 단계부터 다시 (모델 반려 → 이미지부터 검토) |

- 수정 요청은 무엇을 고쳤는지 한 줄로 적어서 다시 보여 준다.
- 같은 단계에서 3번 넘게 수정되면 요청 내용(용도, 느낌)부터 다시 맞춘다.

## 5. 비용 규칙

- 생성마다 포인트가 든다 (이미지 약 20, 모델 약 200).
- 검토를 요청할 때 **이번에 쓴 포인트와 다음 단계 예상 비용**을 같이 적는다.
- 승인이 없으면 비싼 단계(모델)는 돌리지 않는다.

## 6. 파일 위치 (아트 팀장이 넣는 곳 → 오브젝트 세션이 프리팹에 적용)

| 항목 | 위치 |
| --- | --- |
| 모델 파일 | `Assets/04_Resources/Model/<오브젝트 이름>/` |
| 머티리얼 | `Assets/04_Resources/Material/Client/<오브젝트 이름>/` |
| 프리팹 | `Assets/02_Prefabs/Client/Level/<Magic\|Obstacles\|Switches\|Progress>/` |

- 아트 팀장은 모델·머티리얼·애니메이션 파일까지 만들어 위 폴더에 넣는다. 프리팹은 직접 고치지 않는다.
- 오브젝트 세션이 적용할 때: 기존 프리팹이 있으면 겉모습(모델·머티리얼)만 바꾸고 동작 컴포넌트·충돌은 유지, 적용 후 `05_Docs/00_공통/현재_프리팹_리스트.md` 갱신 (CLAUDE.md 규칙).
- 기능(밟으면 튕김 등) 코드 작업은 오브젝트 세션이 CLAUDE.md "오브젝트 구현·테스트" 규칙대로 한다.
