# 서버 작업 착수

VAROGO 서버(Photon Fusion 2, Shared Mode) 작업을 시작한다. **이 단계에서는 코드를 쓰지 않는다.**

## 1. 문서를 순서대로 읽는다

0. `Assets/05_Docs/전달_클라_to_서버.md` — 클라가 서버 파일을 고친 내역·요청. 상태가 `미확인`인 항목을 모두 확인하고, 읽은 항목은 `확인함`으로 바꾼다
1. `Assets/05_Docs/1주차_04_서버착수가이드.md` — 현재 실제 상태, 특히 §7 불일치 목록
2. `Assets/05_Docs/1주차_03_계약명세.md` — 반드시 지킬 규칙
3. `Assets/05_Docs/1주차_02_서버.md` — 작업 목록
4. `Assets/05_Docs/1주차_00_공통.md` — 일정·소유권

필요할 때만: `Assets/05_Docs/현재_프리팹_리스트.md`(Variant 대상), `Assets/05_Docs/1주차_코스디자인.md`(코스 구조).
읽지 않는다: `1주차_01_클라이언트.md` (클라 작업 문서).

문서끼리 충돌하면 **계약명세 > 착수가이드 > 서버 MD > 공통** 순으로 따른다.

## 2. 절대 규칙 (세션 내내 유지)

- `Assets/03_Scripts/Client/`, `Assets/02_Prefabs/Client/`는 수정하지 않는다. 클라 코드는 계약명세 §5 화이트리스트에 있는 것만 호출한다.
- `Assets/03_Scripts/Shared/`를 바꿔야 하면 코드를 고치지 말고 사용자에게 "계약 변경 제안"으로 먼저 알린다.
- Net Variant(`Assets/02_Prefabs/Net/`)는 컴포넌트를 **추가만** 하고 원본 컴포넌트는 제거하지 않는다(계약 R8).
- 온라인 대상 씬은 `11_SpiralCourse`. `10_DemoRoom`은 저장하지 않는다. `11_SpiralCourse` 수정 전에는 사용자에게 "코스 잠금"을 알리라고 상기시킨다.
- Fusion API 동작이 확실하지 않으면 추측해서 쓰지 말고 "확인 필요"로 표시하고 사용자에게 묻는다. 문서에 "확인 필요"로 남은 항목도 같다.
- 클라 소유 파일을 어쩔 수 없이 고쳤거나 클라에 답·요청할 일이 생기면 `Assets/05_Docs/전달_서버_to_클라.md`에 항목을 추가한다.
- 커밋·푸시는 사용자가 직접 한다.

## 3. 보고 후 대기

다 읽은 뒤 아래를 한국어로 짧게 보여주고, **사용자가 승인할 때까지 구현을 시작하지 않는다.**

0. `전달_클라_to_서버.md`의 미확인 항목 요약과, 각 항목에 서버가 할 일
1. 현재 상태 요약 (Fusion 설치 여부, `Assets/03_Scripts/Server/` 상태, `00_Boot` 유무)
2. 오늘 할 작업 계획 — S-01부터 순서대로, 각 작업의 완료 기준
3. 계약 규칙상 걸리는 부분 / 계약 변경이 필요해 보이는 부분
4. "확인 필요" 항목 중 오늘 작업에 걸리는 것
